# Git Committing

This project is a Rust Cargo workspace (Desert City-States). The primary build output directory is `target/`. Other generated outputs may include WASM binaries (from `trunk`), generated Rust code from build scripts, or crate-specific generated artifacts.

## Rules

- Never commit without understanding the intent behind changes
- Never commit secrets, credentials, or sensitive information
- Never commit build artifacts — any file that can be deterministically regenerated by a build tool (compiled binaries, generated code, build output directories, etc.). Lockfiles (e.g., Cargo.lock, package-lock.json) are NOT build artifacts and may be committed normally — they are not deterministic across environments and are intentionally tracked.


## Workflow

1. Read instructions to understand what to stage and why
2. Run `git status` and `git diff --cached` to understand current state
3. Stage exactly what was asked for using `git add <path>`
4. Read content of changed/staged files to understand their purpose
5. Run `git diff --staged` to review what will be committed
6. Review staged files for build artifacts. Check for any file that appears to be a deterministically generated build output (e.g., compiled binaries, files inside `target/`, generated code outside its source location). If any such file is found, abort the commit and report which files and why they appear to be artifacts. Do not guess — if uncertain about a file, err on the side of aborting and flagging it for human review.
7. Write the commit message following conventions below
8. Run `git commit -m "<message>"`
9. Run `git status` to confirm clean working tree

## Commit Message Conventions

- Focus on intent and reasoning, not mechanics of what changed
- Use imperative mood: "Add feature", "Fix bug", "Refactor parser"
- Subject line under 72 characters
- Subject line only, no body (unless complexity demands it)
